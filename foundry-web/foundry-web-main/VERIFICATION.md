# Universal verification policy

Every `uor/template-contract/1` repository satisfies this policy through the
same locked SDK entrypoint. Project-owned verification documentation maps its
features, diagnostics, standards, targets, and planted defects to concrete
evidence.

| Boundary | Required check |
| --- | --- |
| template | `prismpm template check` verifies the exact universal file bytes, contract boundary, policy-input revision, and clean native regeneration in an isolated copy |
| SDK | `prismpm lock check` verifies the immutable SDK manifest and complete artifact inventory selected by `prismpm.lock` |
| model | `just model-write` reproduces project-owned `CONFORMANCE.md`; `just vv` rejects stale or independently edited generated evidence |
| acceptance | `just vv` is the one complete local/devcontainer/CI gate and includes every project-specific positive and negative check |
| dependencies | the lock, vulnerability, license, provenance, and production-dependency closure is checked without path, Git, wildcard, or development-only substitution |
| automation | pull requests have read-only check/build authority; publication, signing, promotion, and deployment are separate protected jobs using short-lived identity |
| reproducibility | generated bytes and platform-independent release graphs reproduce from clean absolute roots through the same SDK digest |

R1--R6 are defined only in `AGENTS.md`. The repository gate must make each one
falsifiable:

- stale generated model evidence fails R1;
- a blurred claim level or vacuous feature mapping fails R2;
- a registered capability without both scenario and test fails R3;
- a deferral, stub, disabled capability, skipped test, or conditional omission
  fails R4;
- an unmodeled public diagnostic or always-pass negative oracle fails R5; and
- a non-production, mutable, or unresolved shipped dependency fails R6.

The universal bootstrap workflow has no publication or deployment credential.
It reads the exact image from `prismpm.lock`, confirms multi-platform Buildx and
the devcontainer CLI, and invokes the repository's own `just vv` on pinned
Linux runners. It copies only Docker's credential configuration into an
ephemeral directory; host CLI plugins never enter the SDK command search path.
It is intentionally outside model-generated output so PrismPM
cannot generate the sole policy that authorizes PrismPM.

This file does not assert that any particular product capability passed. Those
claims belong to the project model, generated `CONFORMANCE.md`, and its
project-owned verification evidence.

## Host baseline (no accepted SDK)

A clean checkout on the pinned host toolchain (rust-toolchain.toml: 1.97.1)
without the accepted SDK reproducibly passes the model and code gates that do
not require it:

- `cargo build --workspace --offline` builds `xtask`, `repo-model`, and
  `repo-conformance`;
- `cargo test --workspace --offline` passes all workspace unit tests across
  the same crates;
- `cargo xtask check-model` reports CONFORMANCE.md equals the model (CM-01)
  with 0 registered ids;
- `cargo xtask audit-limits` reports no shipped crate returns an
  unsanctioned error (R5);
- `cargo xtask audit-deferral` reports no deferral marker (R4);
- `cargo fmt --all -- --check` and
  `cargo clippy --workspace --all-targets -- -D warnings` are clean.

The gates that select and verify the immutable SDK do not run outside it:
`cargo xtask audit-bootstrap` stops at the absent `prismpm.lock` /
`template.lock` and the `PRISMPM_SDK_INVENTORY` selection; `prismpm template
check` and `prismpm lock check` require the SDK binary; `cargo deny` is
supplied by the locked SDK. None of these stops is a product-gate pass: the
conformance registers remain empty and no capability is claimed until the
accepted SDK and its evidence establish it.
