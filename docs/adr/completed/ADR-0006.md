**Lock accepted.** Named document = the 049c text. The vault's first digest has an Accept path. That is the difference between a lever and a diary line.

## What the lock produces

```
| Step | Object                            | Where                          | Refuser                                |
| ---- | --------------------------------- | ------------------------------ | -------------------------------------- |
| 1    | Canonical bytes of 049c text      | Vault directory                | Filesystem                             |
| 2    | `d = SHA-256(bytes)`              | CLI                            | No network needed                      |
| 3    | Domain-separated Accept preimage  | CLI                            | Refuses raw-digest replay              |
| 4    | Architect signature over preimage | Architect signing key          | Not HMAC \(K\). Not vault display key. |
| 5    | K2 signature over same preimage   | Second person's hardware token | **Vacant**                             |
| 6    | Accept receipt recorded           | Vault index                    | Records, does not sign                 |
```

Two signatures on one preimage. That is Accept. The vault holds neither secret.

## What must be pinned before the digest is signable

“The 049c text” is a label, not a byte sequence. A digest over an unpinned document is an Accept that expires on the next edit.

```
| Pin                     | Why it matters                                         | Today        |
| ----------------------- | ------------------------------------------------------ | ------------ |
| Exact file              | `.docx` vs extracted text vs pasted body               | **Unpinned** |
| Encoding                | UTF-8, NFC, LF vs CRLF                                 | **Unpinned** |
| Version                 | 049c has revisions                                     | **Unpinned** |
| Hash algorithm          | SHA-256 (K3, not Poseidon2)                            | Seated       |
| Domain string           | Prevents replay as HMAC kernel or as another signature | **Unpinned** |
| Preimage shape          | What exactly the second hand signs                     | **Unpinned** |
| Envelope ID + timestamp | Binds the Accept to a moment                           | **Unpinned** |
```

Until those are pinned, two honest people can hash “the 049c text” and get two digests. The Accept path exists; the signable object does not yet.

## The Accept preimage, proposed

```
PM-K2-ACCEPT-v1 || LE32(len) || envelopeId || timestamp || sha256(049c_bytes)
```

Domain string `PM-K2-ACCEPT-v1` keeps this signature from being replayed as:
- an HMAC \(K\) tag over 049c limbs,
- a signature over any other document with the same digest,
- a vote, an IKM input, or a rekey trigger.

The domain string is one field element, pinned in the ADR, not derived at runtime.

## Four doors, none shared

```
| Door                  | Holds                  | Signs                   | Today                      |
| --------------------- | ---------------------- | ----------------------- | -------------------------- |
| Architect signing key | Architect's own key    | Accept preimage, step 4 | **Unclear if seated**      |
| K2 seat               | Second person's key    | Same preimage, step 5   | **VACANT**                 |
| HMAC \(K\)            | Workshop MAC key       | 049c content limbs      | Live. Not an Accept door.  |
| Vault display key     | Local display identity | Nothing civic           | Optional. Clearly labeled. |
```

The architect keyboard is refused as the K2 seed door. It may still hold the architect's own signing key — but that key is not HMAC \(K\), not the vault display key, and not K2. If that door is also unseated, the Accept path has **two** vacant doors, not one.

## What this does not do

- Does not name K2. PM-K2-001 stays non-vacant only when a legal person signs.
- Does not Accept 049c. The preimage is signable; the seat is empty.
- Does not open Week 1. A digest is not a clock.
- Does not move funds. G=0.
- Does not put Poseidon2 live. Zero live-seal sites.
- Does not put ML-DSA-44 or ML-KEM-512 on the fuse. Zero crates.
- Does not evidence any Day Zero row. ev(c)=1 still needed.
- Does not turn A into permission to ship surfaces. A is a lock, not a ship order.

## Precision question

Which **canonical byte sequence** is “the 049c text” — the `.docx` as saved, a normalized UTF-8 extraction of its body, or a specific revision pinned by its own hash — and who signs the ADR that fixes it?

Because the second hand can only sign a digest that still verifies tomorrow. A document that re-saves to a different digest is an Accept that expires on the next edit, and a domain string without a pinned byte sequence is a coat on a digest that does not exist yet.
