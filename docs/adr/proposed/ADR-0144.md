# ADR-0144: Ratify ADR-0139 Through ADR-0143, and Stop the Governance Tree Moving Unattended

**Status:** Proposed

## Context
Five records now exist to govern the submodule and Phase Mirror work, and applying the remaining Phase Mirror axes to them finds two things they share and neither addresses.

The first is `urgency vs capacity`. `ADR-0139`, `ADR-0140`, `ADR-0141`, `ADR-0142` and `ADR-0143` are all `Proposed`, and nothing in this repository ratifies a proposal. The status vocabulary spans `Proposed`, `Accepted`, `Completed`, `Superseded` and `Deprecated` across four different directories and three different registries, and the only machine-checked transition is a Rust rule that fails when a *leaked* record is not `Proposed` — there is no rule that promotes a proposal, and no gate that fails because a proposal has sat unratified. Meanwhile the two acknowledgements in `submodule-lockstep.json` point at `ADR-0140`, an unratified record, and `D-21` escalates to a named question about who holds push access. A governance mechanism whose own records are unratified is asking for ratification it has not obtained.

The second is `control desired vs available`, and it is concrete. During this work the working tree acquired an uncommitted migration of roughly sixty files from `docs/adr/accepted/` to `docs/adr/completed/`, plus five new PDFs in `docs/adr/accepted/`. Those files carry September mtimes, so the move is older than this session, yet the tree was clean of it at the start and dirty of it hours later, and no watcher process, no Phase Mirror run and no script this work invoked explains it. Nothing in the repository prevents it recurring: `scripts/check_and_move.py` and `scripts/process_adrs.py` exist to move ADR files between status directories, neither is wired into a gate, and either can rewrite the governance tree with no commit, no review and no notification. The gate this work added, `scripts/check_submodule_integrity.py`, is fail-closed about pins and completely silent about the tree it lives in.

## Decision
Ratification becomes an explicit, checked step rather than an assumption. `ADR-0139` is the only record in this set proposed for `Accepted` on the strength of its own evidence: it is implemented, its gate is armed with 24 unit tests that plant each defect it claims to catch, both repositories pass it, and its residual risk is enumerated rather than assumed away. `ADR-0140` stays `Proposed` because it cannot be executed without push access to two upstream repositories, and `ADR-0141`, `ADR-0142` and `ADR-0143` stay `Proposed` because each describes work not yet performed. A record that describes unperformed work and claims `Accepted` is the exact simulation-masquerading-as-proof failure `D-03` refuses, so status tracks execution rather than intent.

A new gate reports ratification debt rather than hiding it. It enumerates `Proposed` records in the ADR surface, and for each one requires either a `tracked_by` acknowledgement, a register entry, or an age bound after which it is reported as stalled. This is an anti-vacuity check on the register rather than an assertion about the register: "there are no proposed records" is true on an empty repository and uninformative, so the gate reports the count, the oldest age, and the set of records with no tracker, which is false in both an empty and a populated repository in the informative direction.

The ADR-moving scripts stop being able to rewrite the tree unattended. `scripts/check_and_move.py` and `scripts/process_adrs.py` gain a dry-run default and require an explicit `--apply`, so a governance-tree migration is something a person does and reviews rather than something a script does on import or on a timer. The uncommitted `accepted/` to `completed/` migration found during this work is **not** committed by this change and is not resolved by it: it belongs to whoever performed it, and folding an unexplained sixty-file governance migration into a submodule-hygiene pull request would make the pull request unreviewable and would ratify a change nobody here can account for.

## Consequences
* `ADR-0139` becomes the one record of this set that claims `Accepted`, and it does so on evidence a gate re-checks rather than on assertion
* `ADR-0140` through `ADR-0143` remain honestly `Proposed`, so the repository stops presenting unperformed work as decided
* Ratification debt becomes visible as a number and an age rather than as an accumulating pile of proposals nobody has read
* A proposal can no longer sit indefinitely without either a tracker or a stall report, which is the difference between a governance process and a filing cabinet
* `check_and_move.py` and `process_adrs.py` become safe to leave installed: a dry-run default means the sixty-file migration observed here cannot recur unnoticed
* The unexplained migration stays uncommitted and unexplained in this change, which leaves the working tree dirty. That is deliberate: committing it would launder an unaccounted change, and reverting it would destroy whatever produced it. It is reported here instead
* If the migration turns out to be another agent's in-flight work, this repository now has two agents editing `docs/adr/` with no coordination, which is a larger problem than either change in this set and is named rather than resolved
* The ratification gate depends on `ADR-0143`'s work to have a single ADR namespace to enumerate; until then it must tolerate the existing four-directory layout rather than assume one
