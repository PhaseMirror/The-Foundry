# ADR-0142: Give the Phase Mirror Loop the Scanner's Scan Scope Before Running It Again

**Status:** Proposed

## Context
Running the canonical Phase Mirror loop over this tree on 2026-10-03 produced two tensions, and reading them against their evidence shows the loop cannot be trusted as a coverage instrument on this repository. This is `risk claimed vs risk owned`, and the risk is claimed by the tool's own docstring, which claims to "compare stated intent vs implementation reality" across "the Lean 4 corpus".

The measured disagreement is exact. `scripts/phase_mirror_loop.py` hardcodes `LEAN_SUBDIR = "lean"` and reports `lean_decls=156 sorry=0`. `scripts/check_adr_sorry.py`, after the D-15 fix, scans `['ADR', 'Foundations', 'pirtm/lean', 'lean']` and reports **13** manifest-authorised sorry sites, every one of them under `Foundations/Kappa/`. `lake build` agrees with the scanner. So the loop evaluates the repository's sorry-free purity claims against a corpus that excludes every sorry site it exists to police, and reports the plane clean. D-15 gave the scanner the wider scope and did not give the loop the same treatment; the register already logged the symptom as `D-13` at severity Low, describing a stale snapshot rather than a structural blindness, which understates it.

The loop's own top-ranked tension, score 150.0, is an artefact of the same mismatch: `alp_sorry_manifest.json permits 13 sorry(s) not present in lean`. That is not a governance defect in the manifest. It is the loop observing a corpus in which the manifest's permissions necessarily appear unused. Ranking it first means the highest-priority item the methodology surfaces is a measurement error, which is the specific way a reporting tool that always exits 0 corrodes trust in the reports it does produce. The second tension, score 32.0, is real and actionable: two documents — `docs/adr/PM_FORGE_001_Twelve_Card_Workbench_v1.0.md:111` and `docs/adr/Porting TinyLlama.md:215` — claim sorry-free proofs while thirteen sorries are manifested.

A second hazard blocks the obvious remedy. `phase_mirror_loop.py`'s `next_plan_number()` scans `existing_plan_ids()` with a non-recursive `os.listdir` of `docs/adr/`, finds `ADR-PML-001` through `ADR-PML-011`, and returns 12. The `proposed/` directory holds a 227-file `ADR-PML-001`..`ADR-PML-227` series with different content under the same numbers. So a non-dry run today would mint `ADR-PML-012` and write it into `docs/adr/` top level, colliding with a series that already resolves one id to three files in three directories. Any run must be dry until numbering is unified.

## Decision
`phase_mirror_loop.py` adopts `check_adr_sorry.py`'s `SCAN_DIRS` rather than a single `LEAN_SUBDIR`, reusing that module's `scan_lean()` the way `honesty_audit.sh` already reuses it, so the loop and the honesty audit can never again disagree about what is counted. The honesty audit's existing parity check — "loop tally == independent strip-and-count" — is extended to compare against the sorry scanner's scope rather than only against a strip-and-count over the same narrow root, because a parity check between two measurements of the same wrong corpus is not a parity check. `next_plan_number()` stops consulting only `docs/adr/` and instead scans all ADR directories, so a new plan ADR cannot collide with an existing number; until that lands, the loop is not run without `--dry-run`, and this is recorded rather than left to memory.

The tension ranking is corrected only as a consequence of the scope fix, never by hand: the score-150 artefact must disappear on its own once the loop can see `Foundations/Kappa/`. If it does not disappear, the manifest is genuinely stale and a separate decision is required. No tension is deleted, suppressed or renumbered to make the loop's output look clean, which is the `D-03` precedent: weakening an assertion to match an observed value converts a false claim into a passing test.

The two real tensions are recorded rather than resolved. The score-32 purity-claim tension becomes a `D-22` register entry with the two documents cited by path and line, because a document claiming a sorry-free proof while thirteen sorries are manifested is a claim about the repository's honesty boundary, and the honest disposition is either to complete the proofs or to downgrade the wording — an editorial decision with a named owner, not a scanner fix.

## Consequences
* The loop stops ranking a measurement error as its highest-priority finding, so its output becomes usable as evidence for governance decisions instead of something every reader must re-derive
* Two tools that both count sorries can no longer disagree about the corpus, because they will read the same scope by construction rather than by two edits staying in sync
* The parity check in `honesty_audit.sh` gains teeth: it will catch a scope regression in either tool rather than confirming that both are wrong together
* Plan-ADR numbering stops silently colliding with the 227-file `proposed/` series, which is a prerequisite for ever running the loop non-dry without minting a duplicate id
* A non-dry loop run rewrites `docs/adr/ADR-Plan-Phase-Mirror-Dissonance-Loop.md` and its `.backlog.md`, both machine-generated; this record does not authorise that run, and the files are regenerated output that must not be hand-edited
* `D-13` should be re-scoped from a stale snapshot to a structural scope defect and its severity raised, because "the authoritative count is the 13 the scanner reports" is only true for a tool that reads the scanner's scope
* The tension backlog this methodology maintains stays empty and machine-generated, so the hand-authored per-tension detail lives in the register entries and the ADRs instead; that split is recorded here because it is the only durable form the tension detail currently has
* Fixing the scanner without also fixing the loop has now happened once. The parity check above is what makes a second occurrence visible instead of silent
