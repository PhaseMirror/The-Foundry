# ADR-0118: Orchestrator API Documentation

**Status:** Accepted

## Context

The `Orchestrator` struct in `crates/ri1-core/src/orchestrator.rs` lacked a doc comment despite being the central orchestration type. The crate README claims the orchestrator includes meta-engine integration, consent checking, constraint evaluation, and event accumulation. Without documentation, users must read implementation code to discover these capabilities.

## Decision

1. Add a doc comment to `Orchestrator` describing: registry/routing, meta-engine integration, consent check, constraint evaluation, event accumulation, history access via accessors
2. Add doc comments to public methods: `last_meta_events()`, `last_results()`
3. The doc comment explicitly lists available accessors so users discover them without reading source

## Consequences

- Public API is documented
- Users can discover history accessors from doc comment alone
- Method doc comments explain return values and behavior
