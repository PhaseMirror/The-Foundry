# ADR-0137: The Synthesis Response Contract Is Requested and Verified

**Status:** Accepted

## Context
The example package put the synthesis schema inside a prompt string and then trusted the answer, falling back to an empty object when the provider returned nothing. This package had dropped the schema from the prompt entirely, so nothing described the required shape and nothing checked what came back. That combination is what let a hardcoded object pass as a synthesis. A schema that exists only in prose is not a contract: a response missing researchGaps is indistinguishable from a finding that no research gaps exist, and an absent response parsed as {} is indistinguishable from an empty synthesis.

## Decision
SYNTHESIS_SCHEMA is the single source for the shape asked of the model and the shape verified on return. SYNTHESIS_SCHEMA_PROMPT states it to the model with responseMimeType application/json; assertSynthesisShape then refuses any answer that is missing a key, carries an empty overview, has no keyThemes, has a theme without a string-array papers field, or has a non-string-array methodologies, researchGaps, or futureDirections. parseSynthesisJson tolerates one formatting difference, a markdown fence, and nothing else: it never invents a key, never substitutes a default, and never returns an empty object for unparseable text. A shape failure is reported to the client as a 502 with the specific missing key.

## Consequences
* A synthesis cannot reach a client with a missing or empty field, so an absent gap analysis is no longer readable as a finding
* The prompt and the validation share one declaration, so the requested shape and the checked shape cannot drift
* An unparseable provider response is a visible 502 instead of a well-formed empty synthesis
* Shape validation verifies structure only; it is not a detector for fabricated content, and this record does not claim it is one
