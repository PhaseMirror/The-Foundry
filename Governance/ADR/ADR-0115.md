# ADR-0115: Orchestrator History via Interior Mutability

**Status:** Accepted

## Context

The `Orchestrator` struct in `crates/ri1-core/src/orchestrator.rs` declared `last_meta_log: Vec<ResonanceEvent>` and `last_results: Vec<ConstraintResult>` fields, implying accumulated history across calls. However, all public methods take `&self` (immutable reference), making history population impossible without interior mutability. The fields were initialized but never populated. The CLI and library API had no way to inspect accumulated evaluation history.

## Decision

1. Wrap both fields in `RefCell`: `last_meta_log: RefCell<Vec<ResonanceEvent>>`, `last_results: RefCell<Vec<ConstraintResult>>`
2. Change accessors to return owned `Vec<T>` (cloned from `RefCell`)
3. Populate both fields in all evaluation paths: `evaluate()`, `evaluate_with_events()`, `generate()`
4. `generate()` stores both constraint results and resonance events when a meta engine is active

This maintains the existing `&self` API while making history actually accessible and populated.

## Consequences

- `last_meta_events()` and `last_results()` now return actual accumulated data, not empty vecs
- Single-threaded `RefCell` is sufficient (Orchestrator is not `Send`/`Sync` across threads via these fields)
- History grows unbounded; consumers should snapshot and truncate as needed (future ADR)
- Minor runtime cost for `RefCell` borrow checks (negligible for typical evaluation volumes)
