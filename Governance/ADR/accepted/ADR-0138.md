# ADR-0138: Research Governance Context Is Read From the Engine Registry, Not the Hardcoded Set

**Status:** Accepted

## Context
Both research routes built their governance context at module scope from ALL_FOUNDRY_ADRS in lib/adr-data.ts, a hand-maintained array of thirteen records. That array is the same set readEngineRegistry falls back to when the engine registry cannot be read, so the routes presented thirteen hardcoded records as the accepted Architecture Decision Records governing the system, at import time, whether or not the engine was reachable and whether or not those records matched the engine. A module-scope read also cannot report which source it used, so a client had no way to know the governance context it was given was authoritative.

## Decision
The two research routes read governance context per request through readEngineRegistry, the one registry read defined by ADR-0131, and build it with buildGovernanceContext in lib/research-governance.ts. That function asserts a record only when the read came from the engine: a read whose source is fallback yields no governance context and a prompt that states the engine registry is unavailable, so no record id or decision from the hand-maintained array can reach a model. Only Accepted records are asserted, an engine read holding none is reported as holding none, and the source is returned to the client as registrySource so a caller can tell an engine-backed context from a degraded one. This record removes the routes' dependency on ALL_FOUNDRY_ADRS; it does not delete that array, which lib/engine-bridge.ts and lib/mock-data.ts still import and which ADR-0131 governs.

## Consequences
* Governance context in a research answer is traceable to a named source instead of being fixed at thirteen records chosen at import time
* A fallback registry cannot reach a model prompt, which is the failure the routes existed to prevent; the gate is covered by a negative test that plants the removed source check
* A client can distinguish an engine-backed answer from one produced without governance context
* An unreadable registry degrades to explicitly absent context rather than to plausible-looking records
* lib/adr-data.ts remains in use by lib/engine-bridge.ts and lib/mock-data.ts, so the second source ADR-0131 names is not yet closed
