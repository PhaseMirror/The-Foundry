# Hologram-AI × Phase Mirror Agency × Prime (ALP/CNL) — Architecture Integration Analysis

> **Objective**: Identify the strategic synergies between the `hologram-ai` inference engine, the Phase Mirror `Agency` orchestration layer, and the `Prime` formal verification (ALP/CNL) infrastructure. The goal is to outline a concrete roadmap for completely **eliminating reliance on external LLM services** by governing a self-hosted inference pipeline with cryptographically proven, Lean 4-verified constraints.

---

## 1. Subsystem Architecture Overview

### 1.1 Hologram-AI — A Self-Contained, Zero-API Inference Compiler
`hologram-ai` is a pure Rust/WASM client-side AI compiler and execution runtime.
*   **Pipeline**: It downloads HuggingFace models (e.g., Safetensors), compiles them into a weightless intermediate representation (`AiGraph`), and maps constants to content-addressed BLAKE3 hashes via a κ-map to produce a `.holo` archive.
*   **Execution**: Operates without a KV-cache, using κ-elision and staged materialization (windowed execution) to constrain peak memory strictly to the active topological window.
*   **Key Crates**: `hologram-ai-safetensors` (parametric builders), `hologram-ai-common` (IR & optimization), `hologram-ai-core` (event-sourced runner).

### 1.2 Phase Mirror Agency — The Multi-Ensemble Governance Orchestrator
The `Agency` is a multi-agent orchestration layer built around the "Triple-Lock" governance loop (Guardian → Examiner → Publisher).
*   **Orchestration**: A Node.js Express server (`agency-server`) dispatches workloads to Rust binaries implementing strictly defined agent contracts (e.g., *Scopist* for legal, *Ataraxia* for clinical).
*   **Governance API**: Exposes an MCP server (`phase-mirror-mcp`) providing tools like `evaluate_esi_risk` and `verify_ledger` under strict admission constraints.
*   **Archivum**: An immutable JSONL ledger that logs all inter-agent communications and state transitions.

### 1.3 Prime — The ALP & CNL Formal Verification Layer
`Prime` is a formally verified orchestration engine anchored in Lean 4 proofs and recursive STARKs.
*   **CNL Compiler**: Located in `pirtm-apps/src/cnl.rs`, this subsystem translates Controlled Natural Language (CNL) directly into a geometric `MOCWord` Abstract Syntax Tree (AST).
*   **ALP Topology Gate**: The Atomic Language Policy enforces safety invariants geometrically (e.g., $c < 1.0$) *before* execution.
*   **Verification**: Lean 4 proves the absolute impossibility of out-of-bounds mutation or unauthorized command execution, without relying on heuristics.

## 2. Capability Gaps in Hologram-AI

Despite its robust mathematical foundation and zero reliance on external LLM calls, `hologram-ai` currently suffers from isolation:
1.  **Scaling Bottleneck (The Parametric Builder)**: Extending support to new HuggingFace model architectures requires manual, tedious hard-coding inside the massive `parametric.rs` file. Hologram-AI cannot dynamically infer a model's computational graph from unknown configurations.
2.  **No Governance Over Generation**: User-supplied generation parameters (temperature, Top-K, maximum tokens) bypass all policy controls. There is no mechanism to enforce strict determinism (temperature = 0.0) when legally mandated by a domain.
3.  **Disconnected Provenance**: The `AiEvent` sequence generated by Hologram-AI has perfect internal κ-provenance but is not synchronized with the broader, STARK-backed Phase Mirror `Archivum` ledger.
4.  **Static Execution**: It runs a single explicitly targeted model, lacking the intelligence to route specific prompts (e.g., a legal document analysis vs. a creative writing task) to specialized, optimally sized local models.

## 3. The Integration Strategy: How Agency and Prime Complete Hologram-AI

By combining the inference capability of Hologram-AI with the routing of Agency and the formal proofs of Prime, we achieve a locally executing, self-governed intelligence stack.

### Intervention 1: Abductive Graph Generation via Prime's ALP
**The Problem**: Hand-coding topology builders for new HuggingFace architectures is unsustainable.
**The Solution**: We leverage Prime's Abductive Logic Programming (ALP) capabilities.
*   Instead of hardcoding, we parse a new model's `config.json` into ALP facts.
*   Prime's logic solver abduces the optimal `AiGraph` structure (determining, for instance, Grouped-Query Attention vs. Multi-Head Attention based on head counts) and outputs a mathematically verified topology.
*   **Result**: Hologram-AI gains the ability to dynamically compile arbitrary model families safely.

### Intervention 2: Formally Verified Inference Policies (CNL)
**The Problem**: Generation is unguarded.
**The Solution**: Map Hologram-AI's runtime configuration interfaces to Prime's CNL compiler.
*   Policies are defined in plain text: `WHEN domain IS "scopist" THEN temperature MUST BE 0.0`.
*   Prime parses this CNL into a `MOCWord` AST and verifies it through the ALP gate.
*   Before Hologram-AI's `ModelRunner` executes a decode step, it queries the ALP gate. If the parameters violate the accepted CNL policy, the execution is geometrically blocked.

### Intervention 3: Unified Provenance (The Archivum Bridge)
**The Problem**: Hologram-AI's internal logs mean nothing to the broader agency governance.
**The Solution**: Bridge Hologram-AI's event-sourcing (`AiEvent` → `reduce()` → `AiView`) directly into the Agency's REST-based JSONL Archivum.
*   Every model load, compile step, and token generation sequence is cryptographically hashed (`UnifiedWitness`) and logged to the central ledger.
*   This satisfies the Sedona Spine mandate unconditionally: **Policy (Prime CNL) → Event Log (Agency Archivum) → Kernel Computation (Hologram-AI) → Narrative**.

### Intervention 4: Governed MCP Endpoints
**The Problem**: Phase Mirror's MCP server currently relies on feature-gated integrations with external tools like LM Studio for inference.
**The Solution**: Expose Hologram-AI's pipeline as first-class, strictly governed MCP tools:
*   `hologram_compile(model_id)`: Compiles a HF model, subject to an Examiner drift audit.
*   `hologram_generate(prompt)`: Executes inference exclusively on verified `.holo` models, constrained by CNL policies.

### Intervention 5: Multi-Ensemble Inference Routing
**The Problem**: Hologram-AI doesn't know *which* model to run for a given task.
**The Solution**: Use the Agency's orchestration intelligence to drive Hologram-AI dynamically.
*   When a request arrives at the Agency, Prime's ALP solver evaluates the domain (e.g., Legal).
*   The `Scopist` ensemble routes the query specifically to a small, deterministic local model that has been pre-compiled by Hologram-AI, ensuring task-to-model alignment.
