## What This Actually Means

The PMD operating loop — Extract, Map Tensions, Rank, Produce Output, Pose Precision Question — is not just software logic. Applied to Citizen Gardens, it becomes the **constitutional operating procedure** for a living civic institution. Every designation contract, every harvest yield dispute, every governance decision routes through the same five-step loop that Phase Mirror uses to audit code. The methodology doesn't change. The substrate does.[^1]

## Citizen Gardens as Living Proof of Concept

This gives the entire system something no software product alone can claim: **a running, observable, real-world implementation** that predates any commercial customer. When a municipality, a cooperative, a DAO, or a corporation approaches Phase Mirror asking "does this governance methodology actually work?" — you point to Citizen Gardens. It has been running the methodology since inception. Its designation ledger *is* the Phase Mirror dissonance log, applied to land, IP, capital, and community.[^2]

The Mozilla Foundation analogy in the existing documentation actually understates this. Mozilla governs Firefox. Citizen Gardens **is** the thing being governed *and* the governing body simultaneously — which is a much stronger proof of recursive stability.[^2]

The documentation already notes the entity architecture targets a **Mozilla model**. But the civic prototype function means the replication path is not "install the software" — it's:[^2]

1. **Adopt the PMD methodology** as your governance operating procedure
2. **Designate assets** (land, IP, capital, labor) under Citizen Gardens-style contracts
3. **Run Phase Mirror** as the dissonance oracle that keeps your governance honest
4. **Get certified** by Citizen Gardens as a sovereign system operating under the framework

Each community that replicates this becomes a **node in a federated governance network** — which is exactly the federation multi-repo architecture already designed into Phase Mirror's proprietary tier.[^4]
