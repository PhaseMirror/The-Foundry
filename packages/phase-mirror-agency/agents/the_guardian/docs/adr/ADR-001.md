# ADR-001: The Guardian Architecture

- Status: accepted
- Date: 2026-05-26
- Owners: Multiplicity Foundation
- Tags: #guardian, #security, #governance

## 1. Context
'the_guardian' serves as the safety-critical companion to 'the_genius'. While 'the_genius' focuses on zeta-guided optimization, 'the_guardian' is responsible for validating all proposed moves against external legal, governance, and safety constraints.

## 2. Decision
Establish 'the_guardian' as a sidecar service that intercepts all `the_genius` output, applies formal governance policy checks, and only authorizes execution if safety invariants are satisfied.

## 3. Implementation Plan
- Establish a Rust-native inter-process communication (IPC) channel between Genius and Guardian.
- Implement the 'ACEGuardian' safety set $S$ as the gatekeeper.
- Externalize all policy logic into declarative YAML policies stored in `models/the_guardian/policies/`.

## 4. Consequences
- **Positive:** Decouples high-velocity optimization from safety-critical governance.
- **Negative:** Introduces slight latency in the optimization loop (mitigated by asynchronous policy evaluation).

## 5. Security & Governance
This architecture adheres to the **Sedona Spine Mandate** by ensuring all ESI-related decisions are mediated by the Guardian before execution.
