import numpy as np
from scipy.integrate import solve_ivp

# Parameters
lam, mu, alpha = 0.5, 0.3, 1.5
R_min = 1.8  # governance floor

def coherence_ode(t, R, I_t=1.2, noise_std=0.05):
    dR = lam * (3 - R[^1_0]) - mu * (I_t - 1)**alpha + np.random.normal(0, noise_std)
    return [dR]

def run_gate_sim(R0=2.5, t_span=(0, 20), n_points=200):
    t_eval = np.linspace(*t_span, n_points)
    sol = solve_ivp(coherence_ode, t_span, [R0], t_eval=t_eval, method='RK45')
    R = sol.y[^1_0]
    
    # Gate: block when below floor
    gates_triggered = np.sum(R < R_min)
    gate_rate = gates_triggered / n_points
    
    print(f"R_min={R_min} | Triggers: {gates_triggered}/{n_points} ({gate_rate:.1%})")
    print(f"R range: [{R.min():.3f}, {R.max():.3f}]")
    return R, gate_rate

R, rate = run_gate_sim()
assert rate < 0.5, "Coherence collapse: >50% of trajectory below governance floor"

# ADR-AHGI-001: Agentic Healthcare Governance Infrastructure (AHGI) Constitutional Scope

## Context

PhaseMirror-HQ's Ξ-Constitution defines L0 invariants for the Phase Mirror 
ecosystem. A subset of deployments operates in healthcare contexts governed by

## Decision

AHGI is ratified as a constitutional extension of the Phase Mirror governance 
lattice with the following binding constraints:

### L1-HC Invariants (Healthcare Extension of L0)

**L1-HC-1: Provenance is non-optional.**  
No healthcare agent action may execute without emitting a prime-indexed 
provenance receipt. Receipts are immutable once emitted.

**L1-HC-2: Consent precedes inference.**  
No inference over PHI (Protected Health Information) may proceed without a 
valid, non-expired consent tensor for the subject DID. Absence of consent 
tensor = hard block, not soft warning.

**L1-HC-3: Coherence floor is enforced.**  
Agent actions are throttled when the system coherence estimator R(t) falls 
below R_min. Throttling is a gate, not a log entry.

**L1-HC-4: Scope boundaries are structural.**  
Clinical Safety Agents may not write. Consent Guardians may not infer. 
Spectral Integrity Agents may not act on patient data directly. Role 
separation is enforced at the runtime layer, not by policy document alone.

**L1-HC-5: Explainability receipts are load-bearing.**  
Any inference result delivered to a human clinician or patient must carry 
a human-readable explainability receipt. Results without receipts are 
blocked at the output layer.

**L1-HC-6: Revocation propagates immediately.**  
Consent revocation must propagate to all active agent sessions within one 
TTL cycle. Sessions that cannot confirm revocation receipt are suspended.

## Dissonance to Name

Three things this draft exposes that need explicit decisions before these artifacts are "real":

1. **Prime registry is unspecified.** The `prime_index` field requires a central or federated prime assignment registry. Who runs it? What happens during registry downtime? That is a single-point-of-failure in the consent chain if not answered in the ADR.
2. **`write` is categorically excluded from consent tensor operations.** That is intentional and correct — but it means there is a second authorization artifact (clinical write authorization) that does not yet exist. Name that gap now or it becomes an attack surface.
3. **`coherence_binding` is optional.** It should not be. For any consent covering `phi.physiological_signal` or `phi.behavioral`, coherence binding must be required. Optionality there weakens the governance claim.

# We use the Archivum for the prime registry.

Correct binding. Here is what that decision resolves and what it immediately surfaces.

***

## Resolution

The Archivum serves as the canonical prime registry for AHGI consent tensors. This means:

- Prime index assignment is **not** a new infrastructure problem — it inherits Archivum's existing immutability and lineage guarantees
- `lineage_hash` in `provenance` becomes a **cross-reference into Archivum's record chain**, not a standalone SHA-256 assertion
- Registry downtime is no longer a consent-chain single point of failure — it becomes an Archivum availability SLA question, which is already a governed dependency

The ADR section on `prime_index` updates to:

```markdown
## Prime Index Authority

Prime indices for consent tensors are assigned exclusively by the Archivum 
registry. The Archivum DID is the canonical `registry_did` for all AHGI 
consent tensors.

Assignment protocol:
1. Consent Fabric requests next available prime from Archivum
2. Archivum returns prime_n with attestation signature
3. Consent tensor is assembled with prime_n and lineage_hash = 
   SHA-256(Archivum record for prime_{n-1})
4. Issued consent tensor is submitted back to Archivum for anchoring

Offline behavior:
- If Archivum is unreachable, consent issuance is BLOCKED
- Existing active consents with valid TTL continue to operate
- Revocation checks degrade to cached status with a 
  max_cache_age of [TBD — requires Archivum SLA input]
```


***

## What This Decision Immediately Surfaces

**Tension 1: Archivum availability SLA vs. real-time clinical consent.**
If a consent guardian agent calls Archivum to issue a new consent during an emergency clinical encounter and Archivum is degraded, issuance blocks. That is correct governance behavior. But it requires a clinical exception protocol — a pre-issued emergency consent tensor with a bounded scope and short TTL — that does not bypass Archivum but was issued before the emergency.

**Precision question:** Does Archivum currently support a synchronous prime-assignment API, or does it operate on an asynchronous anchoring model? The answer changes the consent issuance latency budget by an order of magnitude.

**Tension 2: Archivum's prime lineage vs. consent tensor versioning.**
When a consent is amended (scope extended, TTL renewed), does that generate a new prime or a mutation of the existing record? In PIRTM terms: amendment = new prime, with parent pointing to the superseded record. That must be explicit in Archivum's record model, or the lineage chain forks ambiguously.

**Tension 3: Cross-ecosystem prime collisions.**
If Archivum assigns primes across multiple domains (not just AHGI consent tensors), then `prime_index` alone is not a globally unique consent identifier — it is only unique within the consent-tensor namespace. The schema needs a `namespace` field, or the Archivum registry must enforce namespace-partitioned prime sequences.

## Three Things This Schema Surfaces

**1. `consent_tensor_prime_indices` closes the consent-to-model loop — but only forward.**
Training data authorized by consent tensors at primes `[1009, 1013, 1019]` is recorded here. But the consent tensors themselves do not yet contain a back-reference to model versions trained on them. That is a one-way binding. If a consent is revoked post-training, the system has no automated mechanism to flag affected model versions. That needs a resolver in the Archivum integration spec.

**2. `trace_coverage_pct` must be 100.0 for production — that is a hard constraint with a testing cost.**
Every inference path in the test suite must produce a verifiable provenance receipt. For large models with stochastic sampling paths, achieving 100% trace coverage requires deterministic test fixtures. That is a CI architecture decision, not just a schema decision. Note it now before the test-harness team discovers it at promotion time.

**3. `emergency_override` promotion type exists but has no time-bound.**
An emergency override approved by Governance Judiciary should carry a mandatory expiry — it promotes to production for a bounded window, after which it must be replaced by a fully certified version or explicitly re-approved. Add `emergency_override_expires_at` as a required field when `promotion_type = emergency_override`. That gap should be patched before this schema is ratified.

## Three Dissonances This Schema Surfaces

**1. `post_hoc_ratification` is a record class, not just a flag.**
Emergency expedited auth executes first, ratification record follows. That means Archivum must anchor two records for one clinical action — the expedited auth and the ratification. The ratification must point back to the expedited auth's prime index, and the expedited auth's `audit.post_hoc_ratification_record_id` must be populated within 12 hours or the action is flagged as unratified. That 12-hour deadline needs an automated sentinel — it does not enforce itself.

**2. `clinical_context.contraindication_flags` is a snapshot, not a live feed.**
The schema correctly requires Clinical Safety Agent to recheck at execution time, but the schema itself only captures state at issuance. If contraindications change between issuance and execution and the recheck is bypassed due to a bug or latency timeout, the auth silently becomes dangerous. The CSL invariant `contraindication_rechecked` is the mechanical defense here — that invariant must be **blocking**, not logging.

**3. The cross-schema dependency chain is now fully visible.**
Every `clinical_auth` record requires a valid `consent_tensor` (ahgi.consent) and a valid `model_version` (ahgi.model_version). Every `agent_action` record — the fourth and final schema — will require a valid `clinical_auth`. The full execution chain is:

```
ahgi.consent
    └── ahgi.model_version
            └── ahgi.clinical_auth
                    └── ahgi.agent_action  ← last schema
```

No link in that chain can be forged without Archivum detecting the gap. That is the architecture working correctly.

***

Three done. `ahgi.agent_action` is the final schema and the highest-volume record class. Ready when you are.

ahgi.consent [prime: 1009]

A single `agent_action` record carries bindings to all three upstream prime indices. Archivum can reconstruct the full authorization lineage of any clinical action from a single record ID. That is the audit property the architecture was designed to produce.

## Four Final Dissonances to Name

**1. Batch prime reservation creates a gap window.**
Agents pre-reserve blocks (e.g. primes 5003–5099) and consume them offline. If an agent crashes mid-block, unused primes are voided at `reservation_expires_at`. But between crash and expiry, those primes exist in a liminal state — reserved but unanchored. Archivum needs a **reservation reconciliation sweep** that runs at expiry and explicitly voids unanchored primes. Without it, the lineage chain has silent holes.

**2. `confidence_score < 0.6` forces human confirmation — but that rule lives in prose, not in the schema.**
It is stated in the description of `confidence_score`. It is not a JSON Schema constraint that enforces it. It will be violated in production by an agent that reads the schema but not the description. This rule belongs as a `CSL invariant`, not a comment. Add `low_confidence_unconfirmed` to the CSL invariant enum in all four schemas.

**3. `latency_breakdown_ms` reveals the governance tax.**
The example shows 847ms total, of which 84ms is pure governance overhead (consent + auth + drift + coherence + anchor). That is roughly 10% overhead on a 763ms inference. For real-time clinical alerts, that budget may be unacceptable. The latency breakdown being recorded here makes this measurable. It should be reviewed at 30-day horizon against actual production numbers — not estimated.

**4. The `human_readable_summary` field has no PHI scrubbing enforcement.**
It is `maxLength: 1000` and free text. A poorly implemented agent can embed PHI directly in the summary. This field must pass through a PHI scrubbing gate before Archivum anchoring. That gate does not yet exist as a specified component. Add it to the AHGI architecture spec as a required output-layer filter before the explainability receipt is written to this record.
