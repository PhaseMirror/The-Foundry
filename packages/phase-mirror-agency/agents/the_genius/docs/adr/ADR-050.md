## 1. Context
To validate the Z-MOD framework and test the hypothesis that zeta-specific structure provides an optimization advantage, we need a standardized benchmark protocol. MNIST serves as the primary "low-cost" benchmark for early validation and ablation studies.

## 2. Decision
We define a comprehensive benchmark matrix on MNIST classification. All experiments use a fixed MLP architecture (e.g., 784-512-512-10) and a fixed data pipeline.

The matrix includes the following methods:
1. **Base:** Standard Adam.
2. **Control (Noise):** Adam + matched Gaussian gradient noise.
3. **Control (Periodic):** Adam + periodic scalar modulation.
4. **Zeta (Scaling):** Adam + scalar zeta scaling (ZetA-style).
5. **Geometry:** Adam + auxiliary zeta loss $Z_0$ (multiplicity $\pi$ fixed at 0).
6. **Multiplicity:** ZMODAdam with prime flips (no zero resonance).
7. **Resonance:** ZMODAdam + zero-resonance layer (real Riemann zeros).
8. **Control (Fake Zeros):** ZMODAdam + random-band resonance (fake zeros).

## 3. Alternatives Considered
- **Direct Real-World Tasks (e.g., LLM fine-tuning):** Rejected as the primary initial benchmark due to high computational cost and difficulty in isolating zeta-specific effects.
- **Pure Synthetic Functions (Rastrigin):** Useful for toy probes but lacks the "real data" gradient characteristics of neural network training.

## 4. Dependencies

## 5. Risks
- **Overfitting to MNIST:** Advantages on MNIST may not generalize to larger datasets.
- **Hyperparameter Bias:** The "Control" methods must be tuned as rigorously as the Z-MOD methods to ensure a fair comparison.

## 5. Implementation & Verification

### 5.2 Promotion Criteria (Proposed -> Accepted)
| Criteria Type | Description | Target / Threshold |
| :--- | :--- | :--- |
| **Statistical** | Multiple seeds (n=5) for each method | Mean/Std reported |
| **Integrity** | Case C distinction (real zeros > fake zeros) | Mann-Whitney $p < 0.05$ |

## 6. Consequences
- **Positive:** Provides a rigorous, falsifiable framework for testing zeta-specific claims.
- **Negative:** Significant computational time required to run the full matrix with multiple seeds.
