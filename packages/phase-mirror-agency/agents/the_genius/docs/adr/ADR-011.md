# ADR-011: ACE Guardian Projection and Contraction Certificates

- Status: accepted
- Date: 2026-05-26
- Owners: Multiplicity Foundation / Citizen Gardens

- Phase: phase-1
- Published-At: models/agios/models/the_genius/docs/adr/ADR-011.md

## 1. Context
The ACE+PETC architecture requires a strict separation between safety (ACE) and learning (PETC). While the "Genius" (PETC) proposes intelligent actions, we need a "Guardian" (ACE) to ensure these actions never violate system stability.

## 2. Decision
We formalize the **ACE Guardian** mechanism:
1. **Contraction Certificates:** Every valid state transition must be accompanied by a "Contraction Certificate," guaranteeing that the system settles toward a stable state (Banach fixed-point theorem).
2. **Safety Projection:** Instead of a simple veto, the Guardian will project any unsafe proposal $\tilde{w}$ onto the nearest point $w^*$ in the mathematically defined safety set $S$.
3. **Certified Weights ($w^*$):** Only weights that have passed through the safety projection can be applied to the system ("Plant").
4. **Scale Normalization:** All signals are normalized to the $[0, 1]$ range to ensure uniform contractivity and numerical stability.

## 3. Alternatives Considered
- **Heuristic Safety Bounds:** Rejected as they lack provable stability guarantees.
- **Strict Veto (Kill Switch):** Rejected as it destroys the intelligent intent of the Genius's proposals; projection preserves performance while ensuring safety.

## 4. Dependencies
- ADR-010: Canonical Embedding
- $\Lambda_m$ (Multiplicity Constant) stability bounds

## 5. Risks
- **Projection Distortion:** If the safety set $S$ is too restrictive, the projected actions $w^*$ might lose the benefit of the original proposals.
- **Computational Cost:** Calculating the "nearest safe point" in high-dimensional space can be expensive (requires efficient optimization like Levenberg-Marquardt).

## 6. Consequences
- **Positive:** Provably safe deployment of high-performance learning models in safety-critical applications.
- **Negative:** Requires rigorous mathematical definition of the "safety set" $S$ for every application domain.
