# ADR-007: Real-time Compliance Tracking and Enforcement

- Status: accepted
- Date: 2026-05-26
- Owners: Multiplicity Foundation / Citizen Gardens
- Tags: governance, compliance, adr-009, auditing
- Phase: phase-1
- Published-At: models/agios/models/the_genius/docs/adr/ADR-007.md

## 1. Context
ADR-009 (Validation-First Gate) establishes a constitutional requirement for reproducible numerical results. To make this an enforceable invariant rather than just a document, we need a real-time compliance tracking system that monitors agent modules, detects deviations, and blocks non-compliant execution.

## 2. Decision
We implement a **Real-time Compliance Tracker** and **Constitutional Gate**:
1. **Module Manifests:** Every agent module must include a `module.adr.json` manifest listing its ADR dependencies and paths to current validation artifacts (e.g., MNIST benchmark hashes).
2. **Tracker Service:** A background process will continuously monitor the repository for changes in manifests and benchmark artifacts, evaluating metrics against defined thresholds.
3. **Automated Auditing:** Generate tamper-evident audit logs for every detection of a deviation or violation of ADR-009.
4. **CI Enforcement:** The `constitutional_gate` CLI will be integrated into the CI/CD pipeline to block merges that fail compliance checks.

## 3. Alternatives Considered
- **Manual Audits:** Rejected as unscalable and prone to human error.
- **Strict CI-only Checks:** Rejected because real-time monitoring is needed for "live" multiplicity configurations that change outside of PR cycles.

## 4. Dependencies
- ADR-009: Constitutional Projector
- ADR-060: Reproducibility and Artifact Packaging

## 5. Risks
- **Operational Overhead:** Monitoring and logging add complexity to the development workflow.
- **Stale Evidence:** High-frequency updates might lead to valid code being flagged as stale if benchmarks aren't re-run immediately.

## 5. Implementation & Verification

### 5.1 Target Artifacts
- **Tool:** `scripts/constitutional_gate.py`
- **Manifest Template:** `docs/adr/templates/module.adr.json`
- **Audit Logs:** `logs/compliance_audit.json`

### 5.2 Promotion Criteria (Proposed -> Accepted)
| Criteria Type | Description | Target / Threshold |
| :--- | :--- | :--- |
| **Detection** | Latency to detect a manual ADR violation | < 5 minutes |
| **Enforcement** | CI blocks PR on missing ADR evidence | 100% enforcement |

## 6. Consequences
- **Positive:** Transforms the "Constitutional Projector" from a theory into an enforceable project invariant.
- **Negative:** Requires developers to maintain up-to-date manifests and evidence files for every governed module.
