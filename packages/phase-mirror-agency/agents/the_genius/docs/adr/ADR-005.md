# ADR-005: Autonomous Genius as a Network Service

- Status: accepted
- Date: 2026-05-26
- Owners: Multiplicity Foundation / Citizen Gardens
- Tags: network, service, orchestration, collaboration
- Phase: phase-1
- Published-At: models/the_genius/docs/adr/ADR-005.md

## 1. Context
The `the_genius` model has established a robust, governed, and self-stewarding intelligence stack. To maximize its impact within the `agiOS` ecosystem, we need a formal mechanism for other agents to consume its capabilities—specifically governed optimization and safety auditing—as a networked service.

## 2. Decision
We define the **Autonomous Genius Service (AGS)** contract:
1. **Service Interface:** A standardized RPC/IPC layer for cross-agent communication.
2. **Named Service Profiles:** Callers may select from standardized profiles (e.g., `MNIST-Fast-Eval`, `CIFAR-Robust-Train`) defined in [AGS-SERVICE-CATALOG.md](../AGS-SERVICE-CATALOG.md).
3. **Mandatory Inputs (The Request):**
   - `profile_name`: Identifier for the requested service mode.
   - `task_spec`: Description of the optimization goal or dataset.
   - `governance_profile`: Optional overrides (default: profile standard).
   - `model_blueprint`: Architectural parameters for PIRTM or standard layers.
3. **Auditable Outputs (The Response):**
   - `artifact_bundle`: Trained weights and reproducibility package (ADR-060).
   - `trajectory_report`: A standardized JSON summary including Genius Type, Phoenix event counts, and steering actions.
   - `evidence_manifest`: Updated `module.adr.json` confirming compliance with the requested ADRs.
4. **Guarantees:** Every AGS call is guaranteed to route through the Constitutional Gate (ADR-007) and the ACE Guardian (ADR-011).

## 3. Alternatives Considered
- **Direct Library Integration:** Rejected because it couples other agents too tightly to the Z-MOD internals and makes cross-language (Rust/Python) integration difficult.
- **Ad-hoc Scripting:** Rejected as it bypasses the constitutional layer and results in un-auditable "shadow" training runs.

## 4. Dependencies
- ADR-007: Real-time Compliance Tracking
- ADR-011: ACE Guardian Projection
- ADR-021: ZMODAdam State Transition
- SPEC-AUTONOMOUS-GENIUS

## 5. Risks
- **Network Latency:** High-volume RPC calls for small optimization steps could slow down the ecosystem. This is mitigated by batching and coarse-grained service tasks.
- **Resource Contention:** Multiple agents requesting training simultaneously. Requires a priority-based scheduler within the service.

## 5. Implementation & Verification

### 5.1 Target Artifacts
- **Service Core:** `src/zmod/service.py`
- **RPC Interface:** `src/zmod/api.py`
- **Schema:** `docs/adr/templates/ags_contract.json`

### 5.2 Promotion Criteria (Proposed -> Accepted)
| Criteria Type | Description | Target / Threshold |
| :--- | :--- | :--- |
| **Integrity** | Service refuses requests missing ADR info | 100% rejection rate |
| **Interoperability** | External agent (e.g., ataraxia) completes a governed run | 1 successful end-to-end |

## 6. Consequences
- **Positive:** Centralizes safety and governance enforcement; enables "optimization-as-a-service" for the entire network.
- **Negative:** Adds a network/IPC layer that must be maintained and secured.
