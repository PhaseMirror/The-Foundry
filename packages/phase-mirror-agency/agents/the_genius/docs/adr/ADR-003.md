# ADR-003: Network Health Intervention Policy

- Status: accepted
- Date: 2026-05-26
- Owners: Multiplicity Foundation / Citizen Gardens
- Tags: network-governance, policy, interventions, health
- Phase: phase-1
- Published-At: models/the_genius/docs/adr/ADR-003.md

## 1. Context
The Global Genius Health dashboard (ADR-004) provides a live signal of the network's cognitive stability. To maintain this stability at scale, we need an automated mechanism that can intervene when network-wide indicators (e.g., Phoenix Rate spikes) exceed safe thresholds.

## 2. Decision
We implement a **Network Governor** with the following intervention policies:
1. **Profile Throttling:** If the Phoenix Rate for a specific profile (e.g., `Research-Deep-Sub`) exceeds 2.0 events/call over a rolling window of 10 calls, the service will temporarily refuse new requests for that profile.
2. **Elevation Gate:** Agents that consistently produce `Unstable / Chaotic` trajectories in `Fast-Eval` are barred from requesting `Robust-Train` until they demonstrate 3 consecutive `Balanced` runs.
3. **Network Cool-down:** If the total Network Phoenix Rate exceeds 5.0 across all profiles, a "Phoenix Reset" is applied network-wide: all non-critical optimization jobs are paused for a 1-hour stabilization period.
4. **Autonomous Policy Updates:** The Governor will log all interventions, which are then used to refine the "Healthy Band" definitions in SPEC-AUTONOMOUS-GENIUS.

## 3. Alternatives Considered
- **Manual Oversight:** Rejected as it cannot respond with the latency required to prevent network-wide instability.
- **Fixed Resource Quotas:** Rejected because it doesn't account for the *quality* of the trajectories, only the volume.

## 4. Dependencies
- ADR-004: Global Genius Telemetry
- ADR-005: AGS Network Service
- ADR-006: Meta-Controller

## 5. Risks
- **Deadlock:** Overly restrictive policies could starve the network of learning opportunities.
- **Intervention Oscillations:** Rapidly enabling/disabling profiles. Mitigation: Hysteresis-based thresholds.

## 5. Implementation & Verification

### 5.1 Target Artifacts
- **Module:** `src/zmod/governor.py`
- **Integration:** `src/zmod/service.py` (Policy Enforcement)

### 5.2 Promotion Criteria (Proposed -> Accepted)
| Criteria Type | Description | Target / Threshold |
| :--- | :--- | :--- |
| **Robustness** | Governor successfully throttles a simulated "runaway" profile | PASS |
| **Stability** | Network Phoenix Rate stabilizes below 1.0 after intervention | Verified in Lab |

## 6. Consequences
- **Positive:** Protects the network from "chaotic contagion"; ensures resources are prioritized for stable, productive learning.
- **Negative:** Adds a layer of "permissioned" optimization that might slow down high-risk research.
