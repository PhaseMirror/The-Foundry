# ADR-060: Reproducibility and Artifact Packaging

- Status: accepted
- Date: 2026-05-26
- Owners: Multiplicity Foundation / Citizen Gardens
- Tags: reproducibility, packaging, devops, research-integrity
- Depends On: ADR-009
- Phase: phase-3
- Published-At: models/the_genius/docs/adr/ADR-060.md

## 1. Context
To ensure that the Zeta Genius research can be verified by the broader community and to satisfy the requirements of a defensive publication, we need a standardized approach to repository structure and experiment tracking.

## 2. Decision
We adopt a standardized repository structure and reproducibility protocol for all Z-MOD artifacts.

**Repository Structure:**
- `src/zmod/`: Core implementation.
- `data/`: Datasets and reference tables (e.g., Riemann zeros).
- `configs/`: YAML configuration files for all experiments.
- `docs/adr/`: Architecture Decision Records.
- `scripts/`: Training and evaluation scripts.
- `tests/`: Unit and integration tests.
- `results/`: Raw experiment data (CSV, JSON, TensorBoard logs).
- `reports/`: High-level analysis and summary reports.

**Reproducibility Rules:**
1. **Config-Driven:** All experiments must be defined in a version-controlled YAML file.
2. **Fixed Seeds:** Every experiment run must log the random seed used.
3. **Log Everything:** Training runs must log $f(\theta)$, $Z_0$, $\pi$ occupancy, resonance scores, and wall-clock time.
4. **ACE Metrics:** Every artifact must include an estimate of its ACE (Absolute Contraction Energy) contribution as per ADR-009.

## 3. Alternatives Considered
- **Ad-hoc Scripting:** Rejected as it leads to "magic numbers" and unreproducible results.
- **Heavy ML-Flow Integration:** Rejected for the initial phase to keep the repository self-contained and easy to clone/run.

## 4. Dependencies
- ADR-009: Constitutional Projector / Validation-First Gate
- Python `pyproject.toml` and `requirements.txt`

## 5. Risks
- **Data Volume:** Logging high-frequency optimizer state (e.g., $t(\theta, \pi)$ at every step) can generate very large log files.
- **Maintenance:** Keeping the repository structure clean requires discipline from all contributors.

## 5. Implementation & Verification

### 5.1 Target Artifacts
- **Document:** `README.md` (updated with repo structure)
- **Tooling:** `src/zmod/logging_utils.py`

### 5.2 Promotion Criteria (Proposed -> Accepted)
| Criteria Type | Description | Target / Threshold |
| :--- | :--- | :--- |
| **Verification** | Third-party can reproduce MNIST Base Adam result | Match within statistical variance |
| **Organization** | All 2026-05-26 ADRs are present in `docs/adr/` | $100\%$ presence |

## 6. Consequences
- **Positive:** High confidence in research results; ease of onboarding for new researchers; solid foundation for peer review.
- **Negative:** Increased initial setup time for new experiments.
