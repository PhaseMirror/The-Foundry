# ADR-030: Prime Multiset Dynamics

- Status: accepted

## 1. Context
While neural network parameters $\theta$ evolve continuously, the multiplicity structure of the Z-MOD framework is fundamentally discrete. The multiplicity vector $\pi$ represents the presence or absence of specific prime-labeled "modes" or "colors" in the optimizer state. We need a robust mechanism to evolve $\pi$ in concert with $\theta$.

## 2. Decision
We implement discrete prime multiset dynamics for $\pi \in M = \{0, 1\}^m$.

The dynamics are governed by a **Metropolis-Hastings (MH)** kernel:
1. **Proposal:** At fixed intervals (or per step), an index $k \in \{1, \dots, m\}$ is selected, and a proposal $\pi'$ is generated by flipping the $k$-th bit: $\pi' = \pi + e_k \pmod 2$.
2. **Acceptance:** The proposal is accepted with probability:
   $$\alpha = \min\left(1, \exp\left(-\beta_{MH} [O(\theta, \pi') - O(\theta, \pi)]\right)\right)$$
   Where $O(\theta, \pi)$ is the total objective (task loss + zeta potential + prime complexity).

Prime complexity is defined as:
$$C(\pi) = \sum_{p \in P} \pi_p \log p$$

## 3. Alternatives Considered
- **Gradient Estimators (Straight-Through):** Treating $\pi$ as continuous during the forward pass and discrete during the backward pass. Rejected because the log-prime shifts in the embedding $s(\theta, \pi)$ are naturally discrete and should be handled as such.
- **Fixed Multiplicity:** Keeping $\pi$ constant throughout training. Rejected because the ability to "jump" between prime sectors is a core feature of the multiplicity-theoretic search strategy.

## 5. Risks
- **Poor Mixing:** The MH chain may get stuck in a local minimum of the multiplicity space if $\beta_{MH}$ is too high or if the prime set $P$ is too large.
- **Step-Size Mismatch:** Rapid changes in $\pi$ might destabilize the continuous Adam moments for $\theta$.

## 6. Consequences
- **Positive:** Allows the optimizer to explore different "arithmetic sectors" of the loss surface; incorporates discrete structural complexity into the learning process.
- **Negative:** Adds stochasticity to the optimization process, which may increase the variance of training results.
