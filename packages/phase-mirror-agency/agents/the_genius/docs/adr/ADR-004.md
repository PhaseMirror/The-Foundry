# ADR-004: Global Genius Telemetry and Health Dashboards

- Status: accepted
- Date: 2026-05-26
- Owners: Multiplicity Foundation / Citizen Gardens
- Tags: telemetry, observability, dashboards, health
- Phase: phase-1
- Published-At: models/the_genius/docs/adr/ADR-004.md

## 1. Context
The Autonomous Genius Service (AGS) now powers multiple agents across the `agiOS` network. To understand system-wide health, exploration trends, and stability issues, we need a centralized mechanism to track and visualize AGS usage patterns.

## 2. Decision
We implement a **Global AGS Telemetry Tracker**:
1. **Event Logging:** Every AGS call must log a standardized event to a persistent store (default: `logs/ags_usage.jsonl`).
2. **Aggregated Metrics:**
   - **Profile Distribution:** Frequency of each named profile (`Fast-Eval` vs. `Robust-Train`).
   - **Pattern Atlas:** Distribution of emergent Genius Types (Balanced, Exploratory, High-Entropy).
   - **Stability Signal:** Network-wide Phoenix event rates and Guardian intervention levels.
3. **Health Dashboard:** A CLI-based utility (`scripts/ags_dashboard.py`) that synthesizes these logs into a "Global Genius Health" report.

## 3. Alternatives Considered
- **Distributed Logging:** Rejected as it makes cross-agent aggregation difficult and slow.
- **Real-time Stream (Prometheus/Grafana):** Future goal; for Phase-1, a local JSONL-based tracker is more portable and aligns with the current repository structure.

## 4. Dependencies
- ADR-005: AGS Network Service
- SPEC-AUTONOMOUS-GENIUS

## 5. Risks
- **Log Bloat:** High-frequency service calls could generate large log files. Mitigation: Compaction/Rotation policy.
- **Privacy:** Log entries must not contain sensitive dataset content, only structural metadata and performance metrics.

## 5. Implementation & Verification

### 5.1 Target Artifacts
- **Module:** `src/zmod/tracker.py`
- **Dashboard:** `scripts/ags_dashboard.py`
- **Persistent Log:** `logs/ags_usage.jsonl`

### 5.2 Promotion Criteria (Proposed -> Accepted)
| Criteria Type | Description | Target / Threshold |
| :--- | :--- | :--- |
| **Visibility** | Dashboard displays metrics from 5+ simulated calls | 100% accurate |
| **Consistency** | Log schema matches SPEC-AUTONOMOUS-GENIUS | PASS |

## 6. Consequences
- **Positive:** Enables system-wide monitoring of "how agiOS is thinking"; identifies struggling tasks or over-taxed profiles.
- **Negative:** Adds a small latency overhead to every AGS call due to logging.
